## 开启路由

在账号编辑中打开“兼容路由”，设置上游模型和协议。保存并更新后，账号 Base URL 会指向本地地址，例如 `http://127.0.0.1:60689/routes/<id>`。

## 端口规则

设置中可以配置默认路由端口。启动时如果该端口被占用，软件会递增端口号并继续探测，直到找到可用端口；成功后记录实际端口，后续优先复用。

## 账号池与故障切换

环境页的“账号池”可以选择参与分发的账号，并设置权重、会话保持时间和失败切换次数。新建账号池默认使用 Responses；Responses 池可以混合 ChatGPT AUTH 与 API Key 账号，Chat Completions 兼容池仍只支持 API Key 账号。

- 新会话先使用当前入口账号，无法识别入口时按权重轮询。
- 同一会话通过会话标识或 `previous_response_id` 保持在已选账号，以提高缓存命中率。
- 仅在限流、额度、超时、网络或上游 5xx 且尚未输出响应时切换一次；400/422 等请求错误不会换账号，流式输出开始后也不会重试。
- 失败账号按 `Retry-After` 或 30 秒、2 分钟、10 分钟的退避进入冷却，之后自动恢复探测。
- AUTH access token、ChatGPT account ID 和上游 API Key 只在路由进程内存中使用；数据库仅保存配置、健康状态、哈希后的会话绑定和脱敏审计记录。

开启账号池后，账号页继续展示每个成员真实的上游 Base URL，而不是 `127.0.0.1` 本地地址，并显示“已开启代理”和“已开启自动分发”。

关闭账号池会恢复各账号原始 Base URL；Chat 兼容账号会恢复为各自的独立兼容路由。删除账号、重命名或删除环境时，关联账号池会同步更新或清理。升级后如果路由进程版本不匹配，应用会重启并从本地配置重新注入凭据。

## 进程生命周期

默认情况下，退出桌面应用不主动关闭路由。设置中的“退出应用时停止路由”开启后，应用退出会尝试停止由 switcher 管理的路由进程。

## 启动排查

如果看到 `ENOENT`，通常是路由目录或运行时文件尚未创建；如果看到 `kill EPERM`，通常是 Windows 进程权限或旧进程已退出。先刷新状态，再重新启动，不要直接删除配置目录。
