# CLI 新窗口项目二级菜单设计

## 目标

账号页的 CLI 操作保留“当前窗口”和“新开窗口”。鼠标悬停“新开窗口”时，不弹出模态框，而是在其右侧展示可滚动的项目二级菜单。选择项目后，在该项目目录启动新的 Codex CLI 窗口。

## 项目来源

- 根据当前操作账号所属环境定位 `CODEX_HOME/config.toml`。
- 读取所有 `[projects."<absolute-path>"]` 表项中的绝对路径。
- 只展示当前仍然存在的目录，自动去重。
- 从同一环境的 `session_index.jsonl` 提取项目最近使用时间；有会话记录的项目按最近使用时间倒序排列，其余项目保持配置顺序。
- 列表末尾提供“选择其他文件夹”和“用户主目录”。
- 不新增独立项目数据库，不修改 Codex 的项目配置。

## 交互

- 悬停 CLI 按钮展示一级菜单。
- 悬停“新开窗口”展示右侧二级项目菜单。
- 一级菜单与二级菜单之间允许短距离移动，不因经过间隙而关闭。
- 二级菜单限制最大高度并支持滚轮滚动；每项展示目录名称和缩略路径，悬停提示完整路径。
- 点击项目后关闭两级菜单，并以所选项目路径启动新窗口。
- “当前窗口”维持现有行为，不展示项目列表。
- “选择其他文件夹”调用系统目录选择器，选择成功后直接启动，但不写入 `config.toml`；Codex 后续产生项目记录后会自然进入列表。

## 启动链路

- 前端将 `target=cli`、`strategy=new-window` 和 `workingDirectory` 一并传给 preload/IPC/bridge。
- bridge 校验目录存在且是目录，避免注入不存在路径或文件路径。
- Unix 启动命令先切换到项目目录，再设置 `CODEX_HOME` 并启动 Codex。
- Windows 启动计划使用对应 shell 的安全目录切换方式。
- 未提供工作目录时，新窗口回退到用户主目录，不再使用应用资源目录。

## 错误处理

- 配置文件不存在或解析失败时，项目菜单仍展示“选择其他文件夹”和“用户主目录”。
- 项目在展示后被删除时，点击会提示目录不存在，并刷新项目列表。
- 读取会话索引失败只影响排序，不影响项目展示。

## 验证

- 配置项目解析、去重、失效目录过滤和会话时间排序单元测试。
- 二级菜单悬停保持、滚动区域和项目选择行为测试。
- `workingDirectory` 从页面到 IPC 再到终端命令的完整传递测试。
- macOS Terminal/iTerm 与 Windows PowerShell/Windows Terminal 的目录转义测试。
- 桌面端完整测试和生产构建。
